# DSCJ 模型能力目录

供 DSCJ 工具箱在不同电脑同步的公开静态模型能力声明。这里不存放 API Key、接口凭据、个人模型配置或会话数据。

## 使用

在支持 GitHub 目录同步的 DSCJ 工具箱中，打开「杂货铺 → 模型」，点击「更新模型目录」。程序从本仓库同一个 Git commit 下载全部目录文件，校验后写入本地缓存。断网或更新失败时保留上一次有效目录。

目录只影响后续在原生模型设置页输入模型 ID 时的能力匹配，不会修改已保存模型或当前草稿。

工具箱 1.6.2 起使用完整提交 SHA 固定全部下载，并检查新提交沿用已缓存的提交历史。只有说明文档变化时，同步仍会确认新的来源提交，但会提示模型声明内容未变化。不要强制推送回退或改写已发布历史；分叉或回退会被安全拒绝。

## 文件格式

- `index.json`：`schemaVersion`、正整数 `revision` 和供应商 JSON 文件名列表。
- 供应商文件：`schemaVersion` 和 `models` 数组。
- 条目包含模型 ID、上下文窗口、最大输出、输入能力和推理参数声明。
- `accounts.json` 描述账号套餐的公共模型能力，不包含任何个人账号记录。

参数映射字符串只是数据，不允许执行。目录声明不代表中转服务实际支持这些能力，请依据服务商文档核实后保存。初始目录是现有项目数据的同步副本，不保证每条声明已通过供应商实测。

## 更新目录

1. 根据可核实的模型服务商资料更新对应 JSON；不要仅改模型名字并照搬旧模型数值。
2. 新增供应商文件时，将它加入 `index.json` 的 `files`；建议每次发布递增 `revision`。
3. 不加入密钥、密码、个人接口地址或其他私密资料。
4. 提交并推送到本仓库；其他电脑点「更新模型目录」即可同步。

修改本地项目的 mox 文件不会自动发布到 GitHub，仍需要提交并推送公开目录更新。
